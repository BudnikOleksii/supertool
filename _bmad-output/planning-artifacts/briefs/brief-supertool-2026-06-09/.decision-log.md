# Decision Log — supertool brief

## 2026-06-09

- **Intent**: Create a product brief for "supertool".
- **Vision (user)**: An umbrella web app of personal internal tools, useful for others too. First tool: a money tracker, analog of RealByte's Money Manager (realbyteapps.com).
- **Stakes (user)**: Test-drive project for BMad + Fable-5 — output will be used to pitch the team at Howly on adopting them. Dual purpose: real product + methodology showcase.
- **Form factor**: Web app. Monorepo merging two existing example repos:
  - `example/track-my-life` — pnpm + Turborepo, Next.js 16 money-tracker frontend (~80% complete, 0% tests)
  - `example/tracker-backend-api` — NestJS + Drizzle + Postgres/Redis API (feature-complete for personal tracker)
- **Hard constraints (user)**:
  - oxlint + oxfmt everywhere (backend migrates off eslint/prettier)
  - Merged AI setup (CLAUDE.md, skills, rules, commands, agents, MCP)
  - Merged .coderabbit.yaml covering both frontend and backend review cases
  - CI adapted for the merged monorepo
- **Research**: Repo extraction digests completed (frontend + backend). Money Manager web-comparable research agent stopped by user — skipped; user knows the reference app firsthand.

### Discovery round 1 (user answers)

- **Product identity**: supertool = umbrella platform ("all my internal tools in one place"). v1 ships only Money Tracker; planner/notes and other tools come later. Architecture should anticipate tool #2 but v1 contains only the tracker.
- **Rebuild, not copy**: example apps are reference material only — their app code is NEVER committed. Built step-by-step, feature-by-feature, with a clean commit history (this history IS the pitch evidence for BMad + Fable-5).
- **What IS carried over (base setup)**: oxlint, oxfmt, .coderabbit.yaml (merged FE+BE), design system (UI package + Storybook), CI workflows, AI tooling (CLAUDE.md, skills, agents, commands, MCP).
- **Stack locked**: Next.js, NestJS, Drizzle ORM, Docker (same as examples). pnpm + Turborepo monorepo.
- **Auth divergence**: try better-auth (better-auth.com) instead of the examples' custom JWT/Passport implementation. Modules/features may diverge from examples in future — examples are inspiration, not contract.
- **Seed data**: example/tracker-backend-api/src/database/data/transactions-02.03.25.json — 1,880 records, flat shape {Date, Category, Type, Amount, Currency}. Real personal data; DB must be seeded with it.
- **Working mode**: Fast path (implied by batch answers) — pending confirmation.

### Discovery round 2 (consolidated gap answers)

- **v1 scope**: Trimmed core — transactions + categories + dashboard + seed import. Recurring, budgets, onboarding flow, settings, accounts/wallets become later epics (more feature-by-feature commits for the pitch story).
- **Test bar**: Tests per feature — every feature lands with its tests in the same story/commit; CI runs them. Pitch evidence: "AI-driven dev ships tested code."
- **Deployment**: Local Docker only for v1 (docker-compose, Postgres). Deployment is a later epic.
- **Auth**: better-auth, email + password only in v1. OAuth later.
- **Open question (deferred to architecture)**: where better-auth lives — it is Next.js-centric, but the API is NestJS; session validation across both must be designed.
- **[ASSUMPTION] Redis**: deferred — example used it for analytics caching; v1 trimmed core doesn't need it yet.
- **[ASSUMPTION] Single-user posture for v1**: built for Oleksii's own data; multi-user sign-up exists via better-auth but no sharing/collab.
