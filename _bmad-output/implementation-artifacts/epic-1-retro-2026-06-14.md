## What Went Well

- **The team learned fast after 1.4.** Once the design-system gaps were understood, the work got measurably better — every UI story after 1.9 carried a screenshot matrix and caught real defects before merge. (Oleksii's headline.)
- **The visual-QA protocol (established 1.9) earned its keep immediately** — caught a Badge contrast defect (~1.3:1, illegible) in 1.10 and Combobox a11y gaps in 1.11. Same class of bug it was built to catch, three more times.
- **Conscious story ordering paid off.** Atoms (1.10) → molecules (1.11) → features (1.5): Story 1.5's auth forms needed *zero* custom form markup — Field, Card, Separator composed cleanly.
- **Disciplined recovery on hard problems.** better-auth's broken CLI peer dep (1.5) → schema generated from `getAuthTables` introspection. Profile redirect loop (1.6) → three designs to land persist-then-navigate. Each solved cleanly, not hacked.
- **Architecture boundaries held** — framework purity in `packages/ui`, generated-client-only API access, money-as-strings rule defined, auth cross-user scoping fully tested with Testcontainers, one-command runtime verified end-to-end.

## Challenges & Growth Areas

- **"Green gates ≠ working UI" was a recurring family of failures, not one bug:**
  - vitest mocks CSS → unit tests can't see a clipped dropdown.
  - turbo cache replays stale logs → local green, CI red (needs `--force`).
  - SCSS `@use` depth breaks are build-only → unit gates stay green, only `pnpm build` catches.
- **1.4 shipped visually broken behind green gates** — Select clipped twice, hardcoded light-theme focus ring breaking dark mode, Poppins silently falling back to `sans-serif`. Cost four unplanned repair stories. Root cause: a UI story with no visual gate, bundling too many concerns (shell + design system + i18n + app frame).
- **Visual-QA + Storybook-a11y assurance is entirely manual** — a dev running a throwaway Playwright+axe script. Worked on discipline; not wired into CI.
- **Bleeding-edge tooling tax** — TS6 (`baseUrl` removed, explicit `rootDir`), Vitest4 (CJS→ES6 SWC recipe), oxlint 1.69 rule removals, recurring pnpm `H.replace` crash, version-table deviations. Absorbed and documented; a steady cost.

## Key Insights

1. A UI story is not "done" on green gates — it's done when someone has **seen** it, in both themes, including open/interactive states. Precondition, not discovery.
2. The "green gates lie" problem is systemic to this stack (CSS mocking + cache + build-vs-unit split) and must be actively defended against, not assumed away.
3. Right-size stories: 1.4 bundled foundation + visual primitives + i18n + app frame with no proof of the visual half. Heavy multi-concern stories breed undetected debt.
4. Empirical verification beats documentation for framework-boundary questions (better-auth basePath, rate limits, pool lifecycle all resolved by hitting the real thing).
5. Reference adaptation, never copy (ED1) — documented divergences (FC typing, framework-purity theme-by-prop, schema-by-introspection) are correct when intentional and justified.
