## What Went Well

- **Infrastructure-first across epic boundaries is now proven twice.** Epic 2 built the D1 decimal-safe harness and the recursive-CTE subtree resolver explicitly *for* Epic 3 — and Epic 3 consumed both with essentially zero rework. The 3.2 roll-up correctly walks to the root (arbitrary depth), anticipating 2.6's restructurable hierarchy; a naive `parent_id` join would have silently under-counted.
- **D1 survived aggregation — the hardest test yet.** Every money figure is SQL `numeric(14,2)::text`; the only `number`s (share %, bar heights) are explicitly fenced as presentation-only at the render boundary. 3.2 proves `sum(breakdown.total) === summary.expense` decimal-safe via `Decimal`.
- **`recharts` introduced by the book** — architecture doc updated first, exact version pinned, app-level only, `'use client'` + `next/dynamic` boundary keeps it out of the server bundle. New-dependency rule fully honored.
- **3.3 resolved a deferral open since 2.2** — the `dateFrom <= dateTo` cross-field guard, via a reusable `IsOnOrAfter` validator caught during review.
- **3.1 seed end-to-end fix beyond the task list** — caught that the dashboard would render zeros despite 1,880 transactions (operator `defaultCurrency` was null) and backfilled it to UAH idempotently. Good "meaningful day one" instinct.
- **Adversarial 3-layer review every story** (Blind Hunter / Edge Case Hunter / Acceptance Auditor) with clean Patch / Defer / Dismiss triage continued from Epic 2.

## Challenges & Recurring Patterns

1. **Visual-QA evidence is ephemeral AND uncommitted — and it regressed.** All three stories captured screenshots to `/tmp` (3.1 `/tmp/vqa`, 3.2 `/tmp/qa-3-2`, 3.3 `/tmp/vqa`); none were committed. Epic 2 at least committed the 2-4 shots into `visual-qa/` — Epic 3 committed zero. Every review flagged the evidence "cannot be re-verified statically" and accepted it on trust. The dark-theme **chart** legibility on 3.3 — the single highest-risk visual defect in the epic, the exact class that shipped broken in 1.4/1.8 — has no durable evidence.
2. **The risk/verification inversion.** The `recharts` chart (3.3) is the most novel UI in the epic, yet it has **no automated render test** (jsdom can't measure `ResponsiveContainer`) **and** the most deferred robustness item (blank-placeholder if a token CSS var resolves empty, no fallback). The riskiest piece is the least machine-verified, and its only safety net — manual QA — left no trace.
3. **Cross-package validation duplication carried in untouched** (Epic 2 Action 5). `POSITIVE_AMOUNT_PATTERN` / `CALENDAR_DATE_PATTERN` are still duplicated API-side (`apps/api/src/shared/constants/transaction-validation.ts`) and frontend-side — contradicting the `shared-constants-no-duplication` rule.
4. **The deferred ledger grows but doesn't consolidate.** The Epic 2 agreement — "a deferral in 2+ stories gets promoted to a root-cause item" — isn't honored; `deferred-work.md` is an append-only log by source.

## Key Insights

1. **Infrastructure-first across epic boundaries is the team's strongest, now twice-proven pattern.** Build the next epic's enabling primitives while in the current one — it pays off with zero rework. Keep doing it.
2. **A manual gate that erodes silently is worse than no gate** — it reads as "covered" in the story record while leaving nothing verifiable. Either machine-enforce it or consciously drop it; the in-between (hand-run, evidence discarded) is the failure mode.
3. **Risk and verification were inversely correlated this epic.** The most novel, highest-defect-risk UI got the least automated coverage. Worth watching as a planning heuristic: novel UI deserves *more* verification, not less.
